# Citadel — локальный агент для Windows

Цитадель получает задачу обычным текстом или голосом, сама выбирает инструменты, выполняет последовательность действий и проверяет результаты. Решения принимает локальная модель через Ollama. Проект рассчитан на разные компьютеры: установщик готовит Python, браузер, зависимости и модель.

Платный API и ключи не требуются. Модель и голос работают локально; поиск и открытие сайтов используют интернет. Голосовой слой использует `faster-whisper` и Silero TTS.

Репозиторий: <https://github.com/chilopek/local-assistant>

## Возможности

- локальная обработка запросов через Ollama;
- выбор модели по режиму производительности;
- вызов инструментов из естественного языка;
- цикл действий с проверкой результата, журналом и остановкой повторяющихся ошибок;
- обычный поиск ограничен временем и числом обращений, после чтения источников агент формирует итог;
- общий поиск в интернете и чтение HTML, JSON, XML и текстовых API;
- отдельный управляемый браузер: страницы, вкладки, ссылки, поля ввода и кнопки;
- чтение окон Windows через UI Automation и взаимодействие с их элементами;
- выполнение Python для вычислений, документов и другой автоматизации;
- чтение и запись файлов, включая абсолютные пути с подтверждением;
- запуск PowerShell-команд с подтверждением;
- запуск приложений с подтверждением;
- простая локальная память на SQLite;
- приватный Python и зависимости внутри EXE; автоматическая подготовка Ollama и выбранной модели;
- создание ярлыка на рабочем столе;
- сборка переносимого EXE-установщика через GitHub Actions;
- два режима микрофона: все команды или команды после слова «цитадель»;
- офлайн распознавание русской речи;
- локальное озвучивание Silero; при ошибке доступен резервный системный голос с явной индикацией;
- чтение текста экрана через Windows OCR, окон через UI Automation и изображений при использовании vision-модели;
- определение примерного города по IP для местных запросов;
- интерфейс с диалогом, панелью активности, подтверждениями и кнопкой остановки;
- глобальная клавиша `Ctrl+Alt+C`;
- режим ожидания ключевого слова `цитадель`.

## Установка на Windows

### Вариант 1: EXE-установщик

Скачайте [готовый `LocalAssistantSetup.exe` из релиза v0.4.0](https://github.com/chilopek/local_voice_assistant-Citadel/releases/download/v0.4.0/LocalAssistantSetup.exe), запустите файл и выберите режим:

- `auto` — автоматический подбор по характеристикам компьютера;
- `fast` — минимальная задержка и небольшая модель;
- `balanced` — рекомендуемый баланс скорости и качества;
- `power` — более сильная модель для производительного компьютера.

Начиная с 0.3, это штатный установщик Inno Setup с готовым приватным Python, Tcl/Tk и библиотеками агента и голоса. На компьютере пользователя не нужны Python, Git и pip; окружение не собирается заново при установке. Приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Citadel` без обязательных прав администратора. Версии библиотек указаны в поставляемом `bundled-packages.txt`.

Настройки, память, журнал, браузер и рабочие файлы хранятся отдельно — в `%LOCALAPPDATA%\LocalAssistant`. Для обновления сначала закройте Цитадель. По умолчанию существующие настройки сохраняются. Старая папка версии 0.2 не удаляется автоматически: её пользовательские данные продолжают использоваться, а при наличии старого `.venv` сохраняется прежний путь рабочей папки.

Ollama и выбранная модель подготавливаются отдельно; нужны интернет и свободное место под модель. Модели речи загружаются при первом голосовом использовании. Выбор «Подготовить Ollama и модель» можно отключить, если вы настраиваете их самостоятельно. Лог этого этапа: `%LOCALAPPDATA%\LocalAssistant\setup-runtime.log`.

Для браузерных задач используется установленный Edge или Chrome. Если они недоступны, установщик загружает Chromium. Агент использует собственный профиль `data/browser-profile`; вход на сайты пользователь выполняет сам. Ярлык запускает GUI через `pythonw.exe`, служебные команды выполняются со скрытой консолью.

### Вариант 2: разработка из исходников (прежний способ)

```powershell
git clone https://github.com/chilopek/local_voice_assistant-Citadel.git local-assistant
cd .\local-assistant
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git"
```

Для выбора режима вручную:

```powershell
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode fast
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode balanced
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode power
```

Для автоматической установки без меню:

```powershell
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode auto -NonInteractive
```

Голос можно явно включить или выключить параметром `-Voice on` / `-Voice off`.

Для обновления уже установленной копии используется параметр `-Update`.

## Требования

- Windows 10 или Windows 11;
- интернет для установки, поиска и веб-задач;
- системный Python для EXE-установщика не требуется; для разработки нужен Python 3.12+;
- Ollama — установщик может поставить её автоматически;
- свободное место под выбранную модель и зависимости;
- микрофон и устройство вывода звука для голосового режима.

Примерная рекомендация по режимам:

| Режим | Ориентир | Приоритет |
|---|---|---|
| `fast` | малый объём RAM или слабый CPU/GPU | скорость и экономия памяти |
| `balanced` | большинство современных компьютеров | баланс скорости и качества |
| `power` | производительный компьютер и больше RAM | качество рассуждений |
| `auto` | любой компьютер | автоматический выбор |

Точные требования зависят от выбранной модели, оперативной памяти, видеопамяти и скорости диска. Установщик показывает обнаруженные характеристики перед выбором.

## Запуск из исходников

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup.ps1
.\scripts\run.ps1
```

Если голосовые зависимости не нужны:

```powershell
.\scripts\setup.ps1 -NoVoice
```

По умолчанию `scripts\run.ps1` открывает графический интерфейс. Для запуска старого терминального режима:

```powershell
.\scripts\run.ps1 -Console
```

Или напрямую из активированного виртуального окружения:

```powershell
py -3.12 -m assistant
```

Локальные настройки можно задать в `assistant.local.json`. Этот файл не добавляется в Git и позволяет выбрать модель, рабочую папку и параметры Ollama для конкретного компьютера.

## Примеры команд

Помощник понимает обычные фразы, например:

- «Покажи файлы в рабочей папке»;
- «Прочитай README.md»;
- «Создай файл notes.txt с этим текстом»;
- «Запусти калькулятор»;
- «Выполни проверку версии Python»;
- «Найди актуальную информацию, прочитай источники и сохрани краткую сводку»;
- «Вычисли сумму из этого CSV и запиши результат в отдельный файл»;
- «Открой сайт, найди нужную страницу и прочитай её».

Это примеры, а не список заранее прошитых команд. Агент комбинирует общие инструменты под новую задачу. Качество зависит от выбранной модели; выполнение любого мыслимого запроса не гарантируется. `read_screen` возвращает снимок, текст Windows OCR и список окон. Изображение передаётся модели только при наличии `vision` в её возможностях Ollama. Текстовая модель использует OCR и UI Automation; распознавание текста может ошибаться и не объясняет содержимое картинок.

`get_location` определяет примерный город по внешнему IP через `https://ipwho.is/`. Это не GPS: VPN и провайдер могут указывать другой город. Для ручного выбора добавьте `"location": "Новосибирск"` в `assistant.local.json`; при заданном городе сетевое определение не выполняется. При недоступности сервиса агент должен уточнить город.

Запуск кода и программ, изменения в интерфейсах и доступ за пределами рабочей папки требуют подтверждения. Отклонение действия останавливает задачу. Кнопка «Остановить» завершает отдельный процесс выполнения, включая зависшие запросы, распознавание и озвучку, и сразу освобождает интерфейс для следующей задачи. Вспомогательные дочерние процессы завершаются; приложения, явно запущенные через `launch_program`, продолжают работать. Уже сделанные изменения автоматически не откатываются.

В голосовом режиме запуск выполняется так:

```powershell
.\scripts\run.ps1
```

Если в локальной конфигурации голос выключен, можно запустить его принудительно:

```powershell
.\.venv\Scripts\python.exe -m assistant --voice
```

Во время работы доступны `/voice` и `/text` для переключения режимов. Для выхода используйте `/exit` или скажите «выход».

В GUI доступны два режима микрофона:

- **После слова «цитадель»** — «Цитадель, найди информацию про SSH» выполняется одной фразой. Можно сначала сказать «Цитадель», а затем в течение 10 секунд произнести команду. Следующая команда снова требует ключевое слово;
- **Все голосовые команды** — каждая распознанная фраза сразу отправляется агенту.

Микрофон включается и выключается кнопкой или глобальной комбинацией `Ctrl+Alt+C`. Конец фразы определяется после примерно 0,7 секунды тишины. Во время ответа и озвучки запись приостанавливается, чтобы помощник не отвечал сам себе. Это последовательное общение, а не одновременное прослушивание во время речи. При первом запуске голосовые модели могут скачиваться; статус загрузки виден в интерфейсе. Ошибки дочернего процесса сохраняются в `data/worker.log`.

## Безопасность

Модель не получает прямой доступ к Windows. Она только предлагает вызов одного из разрешённых инструментов, а приложение отдельно проверяет имя инструмента, аргументы и необходимость подтверждения.

Чтение внутри рабочей папки и создание новых файлов в ней разрешены без дополнительных диалогов. Перезапись файлов, доступ к другим папкам, код, программы и изменения в браузере/Windows подтверждаются отдельно. Python и PowerShell не являются песочницей: проверяйте код в окне подтверждения. Содержимое сайтов и файлов передаётся модели как недоверенные данные. Запись с микрофона удаляется после распознавания.

Журнал действий хранится локально в `data/agent-events.jsonl`, ошибки запуска — в `assistant-launch.log`. Журнал может содержать команды и тексты прочитанных данных; не публикуйте его без проверки.

## Удаление

В установленной версии доступна кнопка **«Удалить помощника…»** в боковой панели. Она запрашивает подтверждение, закрывает приложение, дожидается освобождения его файлов и открывает штатный деинсталлятор. В копии из исходников эта кнопка отключена.

Другой способ: **Параметры Windows → Приложения → Установленные приложения → Citadel → Удалить**. По умолчанию настройки, история, профиль браузера и рабочие файлы сохраняются. В окне удаления можно явно выбрать удаление всех данных из `%LOCALAPPDATA%\LocalAssistant`. Эта операция необратима. Общие Python, Git, Ollama и её модели не удаляются.

Приложение и его приватный Python удаляются независимо от выбора сохранения данных. Если данные сохранены, повторная установка может их использовать. Для автоматического удаления поддерживаются штатные `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`; удаление данных добавляется только явным `/PURGEDATA=1`.

## Сборка EXE-установщика

Для локальной сборки:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r packaging\requirements-win.lock
# Inno Setup нужен только на машине сборки:
winget install --id JRSoftware.InnoSetup -e
.\build-installer.ps1
```

Готовый файл появится в `dist\LocalAssistantSetup.exe`. Сборка копирует полный Windows x64 Python со стандартной библиотекой и Tcl/Tk, добавляет готовые зависимости и изолирует его от системного Python через `._pth`. При повторной сборке кода используйте `-RefreshPayload`; этот режим не меняет уже подготовленные версии библиотек. После изменения зависимостей подготовьте новый payload. GitHub Actions выполняет проверки приложения и сборку штатного установщика.

`-TestBuild` создаёт `LocalAssistantSetupTest.exe` с отдельными AppId, ярлыками и каталогом данных. Он используется только для автоматической проверки установки и удаления и не заменяет рабочую установку.

## Архитектура

```text
пользователь
    ↓
локальное приложение
    ↓
Ollama + выбранная модель Qwen3
    ↓
tool call
    ↓
проверка разрешений и подтверждения
    ↓
действие в Windows
    ↓
результат обратно модели → проверка → следующий инструмент или ответ
```

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File tests\test-installer.ps1
.\.venv\Scripts\python.exe tests\browser_smoke.py
```

При запущенной Ollama можно отдельно проверить реальный выбор инструментов моделью: `tests\live_agent_smoke.py file` и `tests\live_agent_smoke.py web`. Автотесты Windows запускаются на Python 3.12, 3.13 и 3.14.

Полный цикл штатной установки проверяется командой `python tests\native_installer_smoke.py dist\LocalAssistantSetupTest.exe`. Тест проверяет регистрацию в Windows, запуск приватного Python при сломанных системных переменных, сохранение данных по умолчанию, явное удаление данных и сохранность целей junction-ссылок.
