# Citadel — локальный агент для Windows

Цитадель получает задачу обычным текстом или голосом, сама выбирает инструменты, выполняет последовательность действий и проверяет результаты. Решения принимает локальная модель через Ollama. Проект рассчитан на разные компьютеры: установщик готовит Python, браузер, зависимости и модель.

Платный API и ключи не требуются. Модель и голос работают локально; поиск и открытие сайтов используют интернет. Голосовой слой использует `faster-whisper` и Silero TTS.

Репозиторий: <https://github.com/chilopek/local-assistant>

## Возможности

- локальная обработка запросов через Ollama;
- выбор модели по режиму производительности;
- вызов инструментов из естественного языка;
- цикл действий с проверкой результата, журналом и остановкой повторяющихся ошибок;
- обычный поиск ограничен временем и числом обращений, после чтения источников агент формирует итог;
- общий поиск в интернете и чтение HTML, JSON, XML и текстовых API;
- отдельный управляемый браузер: страницы, вкладки, ссылки, поля ввода и кнопки;
- чтение окон Windows через UI Automation и взаимодействие с их элементами;
- выполнение Python для вычислений, документов и другой автоматизации;
- чтение файлов по абсолютным путям и создание новых файлов без подтверждений;
- запуск PowerShell-команд с подтверждением;
- открытие проверенных установленных приложений без подтверждений;
- простая локальная память на SQLite;
- приватный Python и зависимости внутри EXE; автоматическая подготовка Ollama и выбранной модели;
- создание ярлыка на рабочем столе;
- сборка переносимого EXE-установщика через GitHub Actions;
- два режима микрофона: все команды или команды после слова «цитадель»;
- офлайн распознавание русской речи;
- локальное озвучивание Silero; при недоступности его сервера установщик готовит резервный нейроголос Piper;
- голосовые модели скачиваются и проверяются при установке, а не во время первой команды;
- краткая озвучка 1–3 связных предложений; полный ответ остаётся в чате;
- индикатор уровня микрофона с состояниями записи, тишины, перегрузки и паузы;
- чтение текста экрана через Windows OCR, окон через UI Automation и изображений при использовании vision-модели;
- определение примерного города по IP для местных запросов;
- интерфейс с диалогом, панелью активности, подтверждениями и кнопкой остановки;
- глобальная клавиша `Ctrl+Alt+C`;
- режим ожидания ключевого слова `цитадель`.

## Установка на Windows

### Вариант 1: EXE-установщик

Скачайте [установщик Цитадели 0.8](https://github.com/chilopek/local_voice_assistant-Citadel/releases/download/v0.8.0/LocalAssistantSetup.exe), запустите файл и выберите режим:

- `auto` — автоматический подбор по характеристикам компьютера;
- `fast` — минимальная задержка и небольшая модель;
- `balanced` — рекомендуемый баланс скорости и качества;
- `power` — более сильная модель для производительного компьютера.

Начиная с 0.3, это штатный установщик Inno Setup с готовым приватным Python, Tcl/Tk и библиотеками агента и голоса. На компьютере пользователя не нужны Python, Git и pip; окружение не собирается заново при установке. Приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Citadel` без обязательных прав администратора. Версии библиотек указаны в поставляемом `bundled-packages.txt`.

Настройки, память, журнал, браузер и рабочие файлы хранятся отдельно — в `%LOCALAPPDATA%\LocalAssistant`. Для обновления сначала закройте Цитадель. По умолчанию существующие настройки сохраняются. Старая папка версии 0.2 не удаляется автоматически: её пользовательские данные продолжают использоваться, а при наличии старого `.venv` сохраняется прежний путь рабочей папки.

При включённом голосе установщик заранее скачивает выбранный Whisper, проверяет его токенизатор и VAD, загружает нейроголос и выполняет пробный синтез без воспроизведения. Если сервер Silero недоступен, подготавливается русский голос Piper Irina; выбранный движок записывается в настройки. Голос считается подготовленным только после успешной проверки. Ошибка загрузки показывается в установщике; её нельзя принять за готовый голосовой режим. В процессе обработки команд модели не скачиваются. При запуске приложения с включённым голосом отдельный процесс заранее загружает установленные модели в память и прогревает распознавание, VAD и синтез без воспроизведения. Микрофон принимает команды после индикатора готовности. Отмена задачи сохраняет модели; следующая команда использует их повторно. Голосовому процессу запрещены сетевые подключения.

Ollama и выбранная языковая модель также требуют интернета и свободного места. Выбор «Подготовить Ollama и языковую модель» можно отключить, если вы настраиваете их самостоятельно; подготовка включённого голоса при этом сохраняется. Обновление по умолчанию сохраняет выбранные пользователем настройки, включая отключённый голос. Лог: `%LOCALAPPDATA%\LocalAssistant\setup-runtime.log`.

Обычное «открой Google» использует основной браузер Windows через `open_url`. Для задач с чтением страниц, заполнением полей и кнопками используется отдельный управляемый браузер Edge/Chrome, а при их отсутствии — Chromium. У него собственный профиль `data/browser-profile`; вход на сайты пользователь выполняет сам. Открытие отсутствующего Chrome сообщает об отсутствии программы и не запускает установку. Ярлык запускает GUI через `pythonw.exe`, служебные команды выполняются со скрытой консолью.

### Вариант 2: разработка из исходников (прежний способ)

```powershell
git clone https://github.com/chilopek/local_voice_assistant-Citadel.git local-assistant
cd .\local-assistant
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git"
```

Для выбора режима вручную:

```powershell
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode fast
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode balanced
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode power
```

Для автоматической установки без меню:

```powershell
.\install.ps1 -RepoUrl "https://github.com/chilopek/local_voice_assistant-Citadel.git" -Mode auto -NonInteractive
```

Голос можно явно включить или выключить параметром `-Voice on` / `-Voice off`.

Для обновления уже установленной копии используется параметр `-Update`.

## Требования

- Windows 10 или Windows 11;
- интернет для установки, поиска и веб-задач;
- системный Python для EXE-установщика не требуется; для разработки нужен Python 3.12+;
- Ollama — установщик может поставить её автоматически;
- свободное место под выбранную модель и зависимости;
- микрофон и устройство вывода звука для голосового режима.

Примерная рекомендация по режимам:

| Режим | Ориентир | Приоритет |
|---|---|---|
| `fast` | малый объём RAM или слабый CPU/GPU | скорость и экономия памяти |
| `balanced` | большинство современных компьютеров | баланс скорости и качества |
| `power` | производительный компьютер и больше RAM | качество рассуждений |
| `auto` | любой компьютер | автоматический выбор |

Точные требования зависят от выбранной модели, оперативной памяти, видеопамяти и скорости диска. Установщик показывает обнаруженные характеристики перед выбором.

## Запуск из исходников

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup.ps1
.\scripts\run.ps1
```

Если голосовые зависимости не нужны:

```powershell
.\scripts\setup.ps1 -NoVoice
```

По умолчанию `scripts\run.ps1` открывает графический интерфейс. Для запуска старого терминального режима:

```powershell
.\scripts\run.ps1 -Console
```

Или напрямую из активированного виртуального окружения:

```powershell
py -3.12 -m assistant
```

Локальные настройки можно задать в `assistant.local.json`. Этот файл не добавляется в Git и позволяет выбрать модель, рабочую папку и параметры Ollama для конкретного компьютера.

## Примеры команд

Помощник понимает обычные фразы, например:

- «Покажи файлы в рабочей папке»;
- «Прочитай README.md»;
- «Создай файл notes.txt с этим текстом»;
- «Запусти калькулятор»;
- «Выполни проверку версии Python»;
- «Найди актуальную информацию, прочитай источники и сохрани краткую сводку»;
- «Вычисли сумму из этого CSV и запиши результат в отдельный файл»;
- «Открой сайт, найди нужную страницу и прочитай её».

Это примеры, а не список заранее прошитых команд. Агент комбинирует общие инструменты под новую задачу. Качество зависит от выбранной модели; выполнение любого мыслимого запроса не гарантируется. `read_screen` возвращает снимок, текст Windows OCR и список окон. Изображение передаётся модели только при наличии `vision` в её возможностях Ollama. Текстовая модель использует OCR и UI Automation; распознавание текста может ошибаться и не объясняет содержимое картинок.

`get_location` определяет примерный город по внешнему IP через `https://ipwho.is/`. Это не GPS: VPN и провайдер могут указывать другой город. Для ручного выбора добавьте `"location": "Новосибирск"` в `assistant.local.json`; при заданном городе сетевое определение не выполняется. При недоступности сервиса агент должен уточнить город.

Чтение и просмотр файлов, создание новых файлов, скачивание без запуска, открытие обычных документов и папок, сайтов и проверенных установленных приложений выполняются без подтверждений. Поиск, ввод в распознанную форму поиска, переходы по ссылкам, вкладки и фильтры также выполняются автоматически. Для поиска с открытием ответа помощник сначала читает источник, затем открывает его в основном браузере. CAPTCHA остаётся ограничением сайта; помощник не выдаёт её за найденный ответ.

Подтверждение требуется для перезаписи существующих файлов, изменений системных и чувствительных каталогов, запуска кода, установщиков, макросов и неизвестных обработчиков, отправки сообщений и файлов, покупок, платежей и изменений аккаунта. Неизвестные кнопки, последствия которых нельзя определить, также требуют подтверждения.

Кнопка «Остановить» завершает процесс агента и отменяет запись или озвучку, освобождая интерфейс. Отдельный голосовой процесс сохраняет модели в памяти до закрытия приложения. Явно запущенные приложения продолжают работать. Уже сделанные изменения автоматически не откатываются.

Между текстовыми и голосовыми репликами сохраняется один диалог. При сокращении запроса к модели сохраняются недавние реплики, ссылки и пути из результатов инструментов; компактный финал поиска учитывает предыдущий разговор. Это ограниченный контекст текущего диалога, а не бесконечная память. «Новая задача» очищает диалог.

В голосовом режиме запуск выполняется так:

```powershell
.\scripts\run.ps1
```

Если в локальной конфигурации голос выключен, можно запустить его принудительно:

```powershell
.\.venv\Scripts\python.exe -m assistant --voice
```

Во время работы доступны `/voice` и `/text` для переключения режимов. Для выхода используйте `/exit` или скажите «выход».

В GUI доступны два режима микрофона:

- **После слова «цитадель»** — «Цитадель, найди информацию про SSH» выполняется одной фразой. Можно сначала сказать «Цитадель», а затем в течение 10 секунд произнести команду. Следующая команда снова требует ключевое слово;
- **Все голосовые команды** — каждая распознанная фраза сразу отправляется агенту.

Микрофон включается и выключается кнопкой или глобальной комбинацией `Ctrl+Alt+C`. Конец фразы по умолчанию определяется после примерно 1,2 секунды тишины. Полоска под кнопкой микрофона показывает реальный уровень входящего сигнала; красный уровень означает перегрузку. Во время ответа и озвучки запись приостанавливается, чтобы помощник не отвечал сам себе. Индикатор в это время показывает паузу. Ошибки дочернего процесса сохраняются в `data/worker.log`.

Озвучивается короткий связный фрагмент ответа, до трёх предложений, без чтения длинных URL, таблиц и блоков кода. Остальное остаётся в чате. Неполный результат и ошибки не заменяются словом «готово». Сокращение не делает отдельный запрос к языковой модели.

## Фоновые возможности и речь

### Выполнение и проверка результата в 0.8

Просьба сохранить код в файл теперь проверяется отдельно от текста ответа. Создание файла проверяет запись обратным чтением; путь показывается в результате. Если модель вернула один блок кода вместо сохранения, агент может сохранить его через тот же инструмент с обычными правилами разрешений. Для генерируемого Python включается проверка синтаксиса без выполнения. Ограниченная правка двойного экранирования переводов строк применяется только при ошибке синтаксиса и успешной повторной проверке; строковые литералы сохраняются, сложные f-строки автоматически не чинятся. Это не проверка правильности алгоритма.

`find_files` ищет имена/маски рекурсивно с лимитом времени и результатов, без обхода junction/symlink. По умолчанию проверяются пользовательские каталоги, включая перенаправления OneDrive из настроек Windows. Для других дисков можно указать корни. Неполный поиск отмечается `truncated`; отсутствие результата не означает проверку всего компьютера.

`system_status` снимает CPU, RAM, свободное место и дисковый I/O; в Windows через PDH отдельно измеряется активность физического диска. Это отличается от занятого места. При наличии `nvidia-smi` добавляются показатели NVIDIA; отсутствие данных не заменяется выдуманными значениями. `list_processes` показывает PID, память и краткий замер CPU без завершения процессов.

`insert_text` вставляет буквальный Unicode и многострочный код в наблюдённый UI Automation редактор, сохраняя отступы и специальные символы. Буфер обмена восстанавливается через OLE, если пользователь/другое приложение не успели его изменить. Известные редакторы не требуют отдельного разрешения на обычную вставку; неизвестные приложения подтверждаются. Терминалы и распознанные встроенные консоли исключены, чтобы многострочная вставка не стала запуском команд. Полная проверка текста зависит от доступности редактора через UI Automation; отсутствие проверки отражается в результате.

Составное «открой сайт и включи музыку» больше не маршрутизируется как простое открытие. Управляемый браузер показывается, `browser_media` поддерживает HTML audio/video, состояние воспроизведения проверяется. У него отдельный постоянный профиль: для ВК и других сервисов может потребоваться ручной вход. Доступ к аккаунту в основном браузере Windows автоматически не переносится. Совместимость со всеми плеерами и сайтами не гарантируется.

Поиск пробует резервные серверы и управляемый Bing при отказе текстового поиска. Читатель страниц предпочитает текст статьи и убирает навигацию. Конкретные ошибки инструментов остаются в журнале; поиск и сайты могут быть недоступны из-за сети или CAPTCHA.

### Голос, сообщения и модель агента в 0.8

Время и текст установленного напоминания озвучиваются отдельно от общего сокращения ответа. При явной просьбе прочитать файл озвучивается до 6000 символов, включая важные строки в конце этой части; при ограничении сообщается о продолжении. Это не означает чтение большого файла целиком за один раз. Напоминание сопровождается коротким системным сигналом Windows.

Общение стало более кратким и сдержанным, в манере Джарвиса. Во вкладке «Голос» есть профиль `jarvis` с мужским Silero `eugene` и `neutral` с `aidar`. Профиль проверяется синтезом без воспроизведения, затем сохраняется для следующего запуска. Это не копия голоса актёра. Подготовка не меняет отдельно выбранное включение/выключение озвучки.

Во вкладке «Модель агента» можно подготовить другую модель Ollama. Настройка сохраняется только после проверки поддержки tools, применяется после перезапуска. Большая модель требует больше RAM/VRAM и может отвечать медленнее. Исправлены отсутствовавшие в реестре Ollama пресеты `1.7b-instruct`/`8b-instruct` на `qwen3:1.7b`/`qwen3:8b`. Старые такие значения исправляются при настройке установщиком. Уровень планирования по-прежнему зависит от модели; любой произвольный запрос не гарантируется.

### Напоминания, наблюдения и память

В окне **«Дела и память»** доступны напоминания, отмена, перенос на 10 минут, просмотр и удаление постоянных заметок. Примеры: «поставь таймер на десять минут», «напомни через 5 минут проверить архив», «запомни: предпочитаю краткие ответы». Простые таймеры и заметки сохраняются без обращения к языковой модели. Более сложные даты и повторения агент задаёт инструментом `create_reminder`; дата должна включать часовой пояс. Локальный планировщик не вызывает модель для проверки времени.

Напоминания хранятся в SQLite, переживают перезапуск и показываются в чате, всплывающем окне и голосом, если озвучка включена. Они ждут окончания текущего ответа, не прерывают подтверждения и не запускают новую агентную задачу. Пока приложение закрыто или компьютер спит, уведомлений нет; просроченные напоминания появятся после запуска/пробуждения. Повторяющиеся напоминания пропускают пропущенные повторы, не воспроизводя их пачкой.

По просьбе пользователя `watch_process` следит за завершением конкретного PID с проверкой идентичности процесса. `watch_file` ждёт появления файла и его стабильности; это не проверка целостности загрузки. Наблюдения читают метаданные и не запускают программы или файлы. Их также можно отменить в списке.

Постоянная память содержит до 50 явно сохранённых заметок и предпочтений, по 2000 символов каждая. Она включается в контекст новых реплик и сохраняется между запусками. Просмотр и удаление доступны в интерфейсе и через `list_memory`/`forget_fact`. Автоматического наблюдения за экраном или учёта времени в приложениях в этой версии нет.

### Более длинная речь

В версии 0.7 запись ограничена 120 секундами вместо 18, допустимая пауза увеличена до 1,2 секунды. Превышение лимита выдаёт ошибку и не отправляет обрезанную команду агенту. Для настройки доступны `voice_max_seconds` (30–300), `voice_silence_seconds` (0,7–3) и `voice_beam_size` (1–5, по умолчанию 3). Значения применяются после перезапуска.

Обращение «Цитадель» и несколько ограниченных вариантов написания распознаются в начале фразы, в том числе после «эй»/«слушай». Последняя распознанная фраза отображается под настройками голоса, даже если слово активации не было принято. Это распознавание имени средствами Whisper, а не отдельный акустический детектор.

В **«Дела и память → Голос»** можно явно скачать и проверить Whisper `small` для более точного распознавания либо выбрать более быстрый `base`. Настройка меняется только после успешной проверки и применяется после перезапуска. Загрузка выполняется отдельным процессом подготовки; голосовой процесс остаётся без сети. Даже более точная модель может ошибаться; качество зависит от микрофона, шума и речи.

## Проверка разрешений

Модель не получает прямой доступ к Windows. Она только предлагает вызов одного из разрешённых инструментов, а приложение отдельно проверяет имя инструмента, аргументы и необходимость подтверждения.

Чтение файлов и создание новых файлов в обычных пользовательских папках разрешены без дополнительных диалогов, включая пути вне рабочей папки. Перезапись, запись в защищённые каталоги, код, неизвестные программы и действия с внешними последствиями подтверждаются отдельно. Python и PowerShell не являются песочницей: проверяйте код в окне подтверждения. Содержимое сайтов и файлов передаётся модели как недоверенные данные. Запись с микрофона обрабатывается в памяти.

Журнал действий хранится локально в `data/agent-events.jsonl`, ошибки запуска — в `assistant-launch.log`. Журнал может содержать команды и тексты прочитанных данных; не публикуйте его без проверки.

## Удаление

В установленной версии доступна кнопка **«Удалить помощника…»** в боковой панели. Она запрашивает подтверждение, закрывает приложение, дожидается освобождения его файлов и открывает штатный деинсталлятор. В копии из исходников эта кнопка отключена.

Другой способ: **Параметры Windows → Приложения → Установленные приложения → Citadel → Удалить**. По умолчанию настройки, история, профиль браузера и рабочие файлы сохраняются. В окне удаления можно явно выбрать удаление всех данных из `%LOCALAPPDATA%\LocalAssistant`. Эта операция необратима. Общие Python, Git, Ollama и её модели не удаляются.

Приложение и его приватный Python удаляются независимо от выбора сохранения данных. Если данные сохранены, повторная установка может их использовать. Для автоматического удаления поддерживаются штатные `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`; удаление данных добавляется только явным `/PURGEDATA=1`.

## Сборка EXE-установщика

Для локальной сборки:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r packaging\requirements-win.lock
# Inno Setup нужен только на машине сборки:
winget install --id JRSoftware.InnoSetup -e
.\build-installer.ps1
```

Готовый файл появится в `dist\LocalAssistantSetup.exe`. Сборка копирует полный Windows x64 Python со стандартной библиотекой и Tcl/Tk, добавляет готовые зависимости и изолирует его от системного Python через `._pth`. При повторной сборке кода используйте `-RefreshPayload`; этот режим не меняет уже подготовленные версии библиотек. После изменения зависимостей подготовьте новый payload. GitHub Actions выполняет проверки приложения и сборку штатного установщика.

`-TestBuild` создаёт `LocalAssistantSetupTest.exe` с отдельными AppId, ярлыками и каталогом данных. Он используется только для автоматической проверки установки и удаления и не заменяет рабочую установку.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File tests\test-installer.ps1
.\.venv\Scripts\python.exe tests\browser_smoke.py
```

При запущенной Ollama можно отдельно проверить реальный выбор инструментов моделью: `tests\live_agent_smoke.py file` и `tests\live_agent_smoke.py web`. Автотесты Windows запускаются на Python 3.12, 3.13 и 3.14.

Полный цикл штатной установки проверяется командой `python tests\native_installer_smoke.py dist\LocalAssistantSetupTest.exe`. Тест проверяет регистрацию в Windows, запуск приватного Python при сломанных системных переменных, сохранение данных по умолчанию, явное удаление данных и сохранность целей junction-ссылок.
